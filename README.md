# 一問一答アプリ

## 1. このアプリは何か

問題を画面に出し、**声に出して答えると音声認識で文字に起こして正誤を判定する**
Webアプリです。ブラウザだけで動き、サーバー側の処理はありません。

- アプリ本体（`index.html` / `app.css` / `app.js`）は**科目に依存しません**。
  「地理」という語はアプリ本体には一切書かれておらず、すべてデータ側から読み込みます。
- 1科目＝1データファイル。データを差し替えれば、地理以外の科目にもそのまま使えます。
- 現在収録しているのは **共通テスト地理 全28講 828問**（`data/chiri.json`）です。

### ファイルの構成

```
QA_APP/
├─ index.html        アプリ本体（画面の骨組み）
├─ app.css           スタイル（スマートフォン基準の1カラム）
├─ app.js            ロジック（判定・出題・音声認識）
├─ subjects.json     科目の目録。どのデータを読むかを書く
├─ manifest.json     ホーム画面に追加したときのアプリ情報
├─ icon.svg          アイコン（自作のSVG。外部から取得していない）
├─ data/
│   └─ chiri.json    地理828問
├─ tools/
│   └─ csv2json.py   統合CSVから chiri.json を生成するスクリプト
├─ README.md         このファイル
└─ .gitignore
```

## 2. 起動方法

### 2-1. パソコンで開く（ローカル）

**ダブルクリックでは動きません。** ブラウザの安全上の制限（file:// では
同じフォルダのデータを読めない）があるためです。次のどちらかで開いてください。

**方法A：簡易サーバーを立てる（おすすめ）**

`QA_APP` フォルダで PowerShell を開き、

```powershell
python -m http.server 8000
```

そのままブラウザで `http://127.0.0.1:8000/` を開きます。
終わるときは PowerShell で Ctrl+C を押します。

**方法B：Webに公開して開く**

Netlify などに `QA_APP` フォルダをそのまま置けば、URLで開けます。
スマートフォンから使う場合はこの方法になります。公開後は、ブラウザの
「ホーム画面に追加」でアプリのように使えます（`manifest.json` と `icon.svg` が効きます）。

### 2-2. スマートフォンで使う

Web に公開した URL を開き、ブラウザのメニューから「ホーム画面に追加」を選びます。
画面幅が狭いときは自動で1カラムになり、ボタンは指で押せる大きさ（48px以上）になります。

## 3. 問題を修正したいとき

問題文・解答・解説の**正本は統合CSV**です。JSONを手で直してはいけません。

```
1. 統合CSV を直す
   C:\Users\takad\OneDrive\デスクトップ\CHIRI_QA_20260901\CSV\地理一問一答_全講統合.csv

2. QA_APP フォルダで次を実行する
   python tools\csv2json.py

3. data\chiri.json が作り直され、アプリに反映される
```

`csv2json.py` は毎回ゼロから JSON を作り直します。何度実行しても結果は同じです。

### 読み（ひらがな）を足したいとき

音声認識がひらがなで返したときに拾えるよう、`accept`（許容解答）に読みを入れています。
読みの辞書は `tools/csv2json.py` の中の `YOMI` にあります。
解答の文字列をキーにして1行足し、`csv2json.py` を再実行してください。

```python
YOMI = {
    "緯度": ["いど"],
    "新しく足したい解答": ["よみかた"],
}
```

辞書に無い解答でも、漢字表記での照合と部分一致は働きます。

## 4. 科目を追加したいとき

**アプリ本体（index.html / app.js）を書き換える必要はありません。**

```
1. data\ に新しいJSONを置く（例：data\eigo.json）
2. subjects.json に1行足す
```

```json
{
  "subjects": [
    { "id": "chiri", "name": "共通テスト地理", "file": "data/chiri.json", "enabled": true },
    { "id": "eigo",  "name": "英語",           "file": "data/eigo.json",  "enabled": true }
  ]
}
```

科目が1つだけのときは、科目選択の画面を飛ばして単元一覧に進みます。
2つ以上になると、自動で科目選択の画面が出ます。

## 5. データ構造の説明

### 5-1. subjects.json

| キー | 意味 |
|---|---|
| `id` | 科目の識別子（英数字） |
| `name` | 画面に出す科目名 |
| `file` | 問題データのパス |
| `enabled` | `false` にすると「準備中」と表示され、選べなくなる |

### 5-2. 科目データ（data/chiri.json）

| キー | 意味 |
|---|---|
| `subjectId` | 科目の識別子 |
| `subjectName` | 画面に出す科目名 |
| `unitLabel` | 単元の呼び名。地理なら「講」、英語なら「Lesson」、古文なら「章」 |
| `source` | 出典のメモ |
| `updated` | 生成した日付 |
| `units` | 単元の配列 |

`units` の各要素：

| キー | 意味 |
|---|---|
| `id` | 単元番号（"01" など。文字列） |
| `name` | 単元名 |
| `questions` | 問題の配列 |

`questions` の各要素：

| キー | 意味 |
|---|---|
| `no` | 単元内の問題番号 |
| `seq` | 科目全体での通し番号 |
| `section` | 節番号 |
| `level` | 重要度 `S` / `A` / `B` |
| `type` | 出題タイプ `用語` / `理由` / `識別` |
| `q` | 問題文（CSVそのまま） |
| `a` | 解答（CSVそのまま） |
| `exp` | 解説（CSVそのまま） |
| `accept` | 許容解答の配列。用語型・識別型のみ。理由型には付けない |
| `selfCheck` | `true` なら自己採点にする |

**「講」という語はデータ構造の外に出していません。** キー名は `units` で、
表示上の呼び名は `unitLabel` が決めます。これにより、他の科目でも同じアプリが使えます。

## 6. 判定方式の仕様

### 6-1. 自動判定（`selfCheck: false`）

回答を次のように正規化してから、`a` と `accept` の各候補と照合します。

```
・全角と半角を統一する（NFKC）
・カタカナをひらがなに統一する
・英字を小文字にする
・言い淀み（「えーと」など）を先頭から除去する
・語尾（「です」「ます」「だと思います」など）を除去する
・空白・句読点・中黒・括弧・記号・長音を除去する
```

正規化後に**完全一致すれば○**です。加えて**部分一致も○**にします。
ただし誤って○にしないよう、次の両方を満たす場合に限ります。

```
・短いほうの文字列が3文字以上
・短いほうが長いほうの50%以上の長さ
```

- 例：正解「正距方位図法」に対し「正距方位」→ ○（4文字／6文字＝67%）
- 例：正解「正距方位図法」に対し「図法」→ ×（2文字なので部分一致を認めない）

### 6-2. 自己採点（`selfCheck: true`）

自動判定を**行いません**。回答と模範解答・解説を並べて表示し、
`○ 合っていた` / `× 違っていた` を本人が押します。

**なぜ理由型を自己採点にするのか。**
理由を述べる問題は表現の幅が広く、正しい答えでも言い回しが違えば機械照合では×になります。
誤って×にされると学習の妨げになるうえ、模範解答と自分の答えを見比べる作業そのものに
学習効果があるためです。手抜きではなく、意図した仕様です。

**どの問題が自己採点になるか。**

```
・出題タイプが「理由」の問題　　　　　　　　　→ すべて
・出題タイプが「識別」で、解答が40字を超える問題 → 自己採点
```

この判定は**データ側の `selfCheck` フラグ**で決まります。アプリは
出題タイプを見ていません。将来の科目で判定方式を変えたいときは、
`tools/csv2json.py` の `SELF_CHECK_LEN` や条件を変えて JSON を作り直すだけで、
アプリ本体を触る必要はありません。

現在の内訳：**自動判定 462問／自己採点 366問**（合計828問）

## 7. 音声認識が動かないときの原因と対処

音声認識は **Web Speech API**（`webkitSpeechRecognition`、`lang="ja-JP"`）を使っています。
このAPIは**ブラウザ内で完結せず、認識サーバーと通信します**。そのため次の条件が要ります。

| 症状 | 原因 | 対処 |
|---|---|---|
| 音声ボタンが出ない | ブラウザが未対応（Firefox など） | Edge か Chrome を使う。キーボード入力でも最後まで使える |
| 「マイクの利用が許可されませんでした」 | マイクの許可を拒否した | ブラウザのアドレスバーの鍵アイコンから許可し直す |
| 「音声認識サービスに接続できませんでした」 | 認識サーバーに到達できない（ネットワーク制限・オフライン） | ネットワークを確認する。解消しない場合はキーボード入力を使う |
| `file://` で開くと動かない | ブラウザの制限でマイクが使えない | 上の「起動方法」のとおり `http://` で開く |
| 聞き取れない・別の語になる | 同音異義語や発音の癖 | `tools/csv2json.py` の `YOMI` に読みを足して作り直す |

**このアプリは音声が使えなくても止まりません。**
音声が使えないと分かった時点で、自動的にキーボード入力欄が出ます。
「拒否」以外の理由（ネットワークなど）の場合はマイクボタンが有効なままなので、
あとでもう一度試すこともできます。
