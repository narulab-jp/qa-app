# 一問一答アプリ

**公開URL： https://narulab-jp.github.io/qa-app/**

スマホでの設定手順は [スマホ設定手順.md](スマホ設定手順.md)（PDF版：`スマホ設定手順.pdf`）にあります。
息子さん本人が自分で設定できるよう、専門用語を使わずに書いています。


## 1. このアプリは何か

問題を画面に出し、**声に出して答えると音声認識で文字に起こして正誤を判定する**
Webアプリです。ブラウザだけで動き、サーバー側の処理はありません。

- アプリ本体（`index.html` / `app.css` / `app.js`）は**科目に依存しません**。
  「地理」という語はアプリ本体には一切書かれておらず、すべてデータ側から読み込みます。
- 1科目＝1データファイル。データを差し替えれば、地理以外の科目にもそのまま使えます。
- 現在収録しているのは **共通テスト地理 全28講 828問**（`data/chiri.json`）です。

### できること

| 機能 | 内容 |
|---|---|
| 単元から出題 | 単元を複数選び、出題数・重要度・出題順を指定して出題 |
| **間違いノート** | 単元をまたいで、間違えた問題だけを蓄積。連続正解で卒業 |
| **周回学習** | 選んだ範囲を**全問正解するまで終わらない**モード。中断・再開できる |
| **学習ログ** | 所要時間・初回正答率・タイプ別／重要度別の正答率・時間のかかった問題 |
| **印刷** | 間違いノートをA4縦で印刷（チェック欄つき） |
| **PWA** | ホーム画面に追加してアプリとして起動。Service Workerでオフライン対応 |
| 設定 | 卒業に必要な連続正解数・既定の出題数・音声の自動開始・文字サイズ |

## 2. 起動方法

### 2-1. パソコンで開く（ローカル）

**ダブルクリックでは動きません。** ブラウザの安全上の制限（file:// では
同じフォルダのデータを読めない）があるためです。次のどちらかで開いてください。

**方法A：簡易サーバーを立てる（おすすめ）**

`QA_APP` フォルダで PowerShell を開き、

```powershell
python -m http.server 8000
```

そのままブラウザで `http://127.0.0.1:8000/` を開きます。
終わるときは PowerShell で Ctrl+C を押します。

**方法B：公開済みのURLを開く（おすすめ）**

    https://narulab-jp.github.io/qa-app/

GitHub Pages で公開しています。スマートフォンから使う場合はこちらです。

### 2-2. スマートフォンで使う（PWA）

Web に公開した URL を開き、ブラウザのメニューから「ホーム画面に追加」を選びます。
アイコンから起動すると、アドレスバーのないアプリのような画面になります。

- 画面幅が狭いときは自動で1カラムになり、ボタンは指で押せる大きさ（48px以上）になります。
- 2回目以降は Service Worker のキャッシュが効き、**オフラインでも問題を解けます**。
- ただし**オフラインでは音声認識は使えません**（下記7参照）。その場合は自動で
  キーボード入力に切り替わり、画面にその旨が出ます。

## 3. 問題を修正したいとき

問題文・解答・解説の**正本は統合CSV**です。JSONを手で直してはいけません。

```
1. 統合CSV を直す
   %USERPROFILE%\OneDrive\デスクトップ\CHIRI_QA_20260901\CSV\地理一問一答_全講統合.csv

2. QA_APP フォルダで次を実行する
   python tools\csv2json.py

3. data\chiri.json が作り直され、アプリに反映される
```

`csv2json.py` は毎回ゼロから JSON を作り直します。何度実行しても結果は同じです。

**問題を削除・差し替えしても、間違いノートは壊れません。**
ノートは通し番号（`seq`）だけを保存しており、読み込み時に現在の問題データと
突き合わせて、存在しない番号は無視し、その件数を画面に表示します。

### 読み（ひらがな）を足したいとき

音声認識がひらがなで返したときに拾えるよう、`accept`（許容解答）に読みを入れています。
読みの辞書は `tools/csv2json.py` の中の `YOMI` にあります。
解答の文字列をキーにして1行足し、`csv2json.py` を再実行してください。

```python
YOMI = {
    "緯度": ["いど"],
    "新しく足したい解答": ["よみかた"],
}
```

辞書に無い解答でも、漢字表記での照合と部分一致は働きます。

### アイコンを作り直したいとき

```powershell
python tools\make_icons.py
```

`icons/` の3つのPNGが作り直されます。外部から画像は取得していません。

## 4. 科目を追加したいとき

**アプリ本体（index.html / app.js）を書き換える必要はありません。**

```
1. data\ に新しいJSONを置く（例：data\eigo.json）
2. subjects.json に1行足す
```

```json
{
  "subjects": [
    { "id": "chiri", "name": "共通テスト地理", "file": "data/chiri.json", "enabled": true },
    { "id": "eigo",  "name": "英語",           "file": "data/eigo.json",  "enabled": true }
  ]
}
```

科目が1つだけのときは自動でその科目が選ばれます。2つ以上になると選べるようになります。
保存されるファイル名は科目ごとに変わります（`chiri_note.json` / `eigo_note.json` など）。

## 5. データ構造の説明

### 5-1. subjects.json

| キー | 意味 |
|---|---|
| `id` | 科目の識別子（英数字） |
| `name` | 画面に出す科目名 |
| `file` | 問題データのパス |
| `enabled` | `false` にすると「準備中」と表示され、選べなくなる |

### 5-2. 科目データ（data/chiri.json）

| キー | 意味 |
|---|---|
| `subjectId` | 科目の識別子。保存ファイル名の頭にも使われる |
| `subjectName` | 画面に出す科目名 |
| `unitLabel` | 単元の呼び名。地理なら「講」、英語なら「Lesson」、古文なら「章」 |
| `source` | 出典のメモ |
| `updated` | 生成した日付 |
| `units` | 単元の配列 |

`units` の各要素：`id`（単元番号・文字列）／`name`（単元名）／`questions`（問題の配列）

`questions` の各要素：

| キー | 意味 |
|---|---|
| `no` | 単元内の問題番号 |
| `seq` | 科目全体での通し番号。**間違いノートはこの番号で問題を特定する** |
| `section` | 節番号 |
| `level` | 重要度 `S` / `A` / `B` |
| `type` | 出題タイプ `用語` / `理由` / `識別` |
| `q` `a` `exp` | 問題文・解答・解説（CSVそのまま） |
| `accept` | 許容解答の配列。用語型・識別型のみ。理由型には付けない |
| `selfCheck` | `true` なら自己採点にする |

**「講」という語はデータ構造の外に出していません。** キー名は `units` で、
表示上の呼び名は `unitLabel` が決めます。

### 5-3. 間違いノート（chiri_note.json）

```json
{
  "subjectId": "chiri",
  "updated": "2026-09-02T14:30:00+09:00",
  "entries": [
    { "seq": 45, "unitId": "02", "no": 18,
      "wrongCount": 3, "correctStreak": 0,
      "firstWrong": "...", "lastWrong": "...", "lastCorrect": null }
  ],
  "history": [],
  "settings": { "graduateStreak": 2, "defaultCount": 20,
                "autoMic": false, "fontSize": "normal" }
}
```

| キー | 意味 |
|---|---|
| `seq` | 問題を特定する通し番号。**問題文は保存しない**（本文を直しても古い文言が残らない） |
| `wrongCount` | 累計で間違えた回数。**正解しても減らさない**（弱点の履歴として残す） |
| `correctStreak` | 連続正解数。`settings.graduateStreak` に達すると `entries` から外れる |
| `settings` | 設定。ノートと一緒に保存される |

**出入りの規則**

```
間違えた → entries に追加（既にあれば wrongCount +1、correctStreak を 0 に）
正解した → correctStreak +1
correctStreak が既定値（2）に達した → entries から外す（卒業）
```

1回正解しただけでは消しません。まぐれ当たりで消えるのを防ぐためです。
この回数は設定画面で 1〜3 に変えられます。

### 5-4. 学習ログ（chiri_log.json）

セッションごとに1件たまります。`elapsedSec`（所要時間）、`totalAsked`（出題した実数）、
`firstTryCorrect`（初回で正解した数）、`firstTryRate`、`byType` / `byLevel`
（タイプ別・重要度別の出題数と正解数）、`slowest`（時間のかかった上位10問）を含みます。

**正答率は「初回の解答」だけで計算します。** 周回モードの再出題での正解を含めると
必ず100%になり、指標として意味がなくなるためです。

### 5-5. 中断ファイル（chiri_resume.json）

周回モードで「中断して保存」を押すと作られます。ホームの
「中断した周回を再開する」から読み込むと、周回数・残り問題・経過時間ごと復元されます。

## 6. 判定方式の仕様

### 6-1. 自動判定（`selfCheck: false`）

回答を次のように正規化してから、`a` と `accept` の各候補と照合します。

```
・全角と半角を統一する（NFKC）
・カタカナをひらがなに統一する
・英字を小文字にする
・言い淀み（「えーと」など）を先頭から除去する
・語尾（「です」「ます」「だと思います」など）を除去する
・空白・句読点・中黒・括弧・記号・長音を除去する
```

正規化後に**完全一致すれば○**です。加えて**部分一致も○**にします。
ただし誤って○にしないよう、次の両方を満たす場合に限ります。

```
・短いほうの文字列が3文字以上
・短いほうが長いほうの50%以上の長さ
```

- 例：正解「正距方位図法」に対し「正距方位」→ ○（4文字／6文字＝67%）
- 例：正解「正距方位図法」に対し「図法」→ ×（2文字なので部分一致を認めない）

### 6-2. 自己採点（`selfCheck: true`）

自動判定を**行いません**。回答と模範解答・解説を並べて表示し、
`○ 合っていた` / `× 違っていた` を本人が押します。

**なぜ理由型を自己採点にするのか。**
理由を述べる問題は表現の幅が広く、正しい答えでも言い回しが違えば機械照合では×になります。
誤って×にされると学習の妨げになるうえ、模範解答と自分の答えを見比べる作業そのものに
学習効果があるためです。手抜きではなく、意図した仕様です。

**どの問題が自己採点になるか**

```
・出題タイプが「理由」の問題　　　　　　　　　→ すべて
・出題タイプが「識別」で、解答が40字を超える問題 → 自己採点
```

この判定は**データ側の `selfCheck` フラグ**で決まります。アプリは出題タイプを見ていません。
将来の科目で判定方式を変えたいときは、`tools/csv2json.py` の `SELF_CHECK_LEN` や
条件を変えて JSON を作り直すだけで、アプリ本体を触る必要はありません。

現在の内訳：**自動判定 462問／自己採点 366問**（合計828問）

### 6-3. 周回モードが終わらないときは

周回モードは全問正解するまで続きます。理由型は自己採点なので、
×を押し続けると終わりません。**画面下の「中断して保存」を押せばいつでも抜けられます。**
保存したファイルから、あとで続きを再開できます。

## 7. 音声認識が動かないときの原因と対処

音声認識は **Web Speech API**（`webkitSpeechRecognition`、`lang="ja-JP"`）を使っています。
このAPIは**ブラウザ内で完結せず、認識サーバーと通信します**。そのため次の条件が要ります。

| 症状 | 原因 | 対処 |
|---|---|---|
| 音声ボタンが出ない | ブラウザが未対応（Firefox など） | Edge か Chrome を使う。キーボード入力でも最後まで使える |
| 「マイクの利用が許可されませんでした」 | マイクの許可を拒否した | ブラウザのアドレスバーの鍵アイコンから許可し直す |
| 「音声認識サービスに接続できませんでした」 | 認識サーバーに到達できない（ネットワーク制限） | ネットワークを確認する。解消しない場合はキーボード入力を使う |
| 「オフラインのため音声認識は使えません」 | オフライン | オフラインでは仕様上使えない。キーボード入力で解く |
| `file://` で開くと動かない | ブラウザの制限 | 上の「起動方法」のとおり `http://` で開く |
| 聞き取れない・別の語になる | 同音異義語や発音の癖 | `tools/csv2json.py` の `YOMI` に読みを足して作り直す |

**このアプリは音声が使えなくても止まりません。**
音声が使えないと分かった時点で、自動的にキーボード入力欄が出ます。
「拒否」以外の理由（ネットワーク・オフラインなど）の場合はマイクボタンが有効なままなので、
あとでもう一度試すこともできます。

### 確認済みの状況（2026-09-02 時点）

作業に使ったPCでは、`onstart`（認識の開始）までは動作しましたが、
その直後に `error:network` となり、認識結果は得られませんでした。
画面ありのEdgeでも同じでした。**このPC・ネットワークから認識サーバーへ到達できていない**
状態です。Web公開後に別のネットワークから再確認してください。

## 8. データの保存について

**このアプリはブラウザにデータを保存しません**（localStorage / sessionStorage を使いません）。
間違いノートと学習ログは、**ファイルとして書き出して手元に残す**方式です。

```
書き出し：画面の「ノートを保存」「学習ログを保存」を押すとダウンロードされる
読み込み：ホームの「前回のノートを読み込む」からファイルを選ぶ
```

- 起動したら、まず**「前回のノートを読み込む」**を押してください。
- 読み込まずに始めようとすると「ノートなしで始めますか」と確認が出ます。
- 未保存の変更があるまま画面を閉じようとすると、ブラウザが警告を出します。
- セッションが終わると、結果画面の上部に「ノートを保存する」が出ます。

**保存を忘れると、その回の学習の記録は残りません。** 終わったら必ず保存してください。

## 9. Service Worker（オフライン対応）について

`sw.js` が `index.html` / `app.css` / `app.js` / `subjects.json` / `manifest.json` /
アイコンをキャッシュします。科目データは一度読み込むと自動でキャッシュされます。

- キャッシュ優先、ネットワークはフォールバックです。
- キャッシュ名にバージョン（`qa-app-v1`）を持たせ、更新時に古いキャッシュを消します。
  **アプリを更新したら `sw.js` の `VERSION` を上げてください。**
- **`file://` では動きません。** https（または localhost）で配信して初めて有効になります。
- 登録に失敗してもアプリは普通に動きます（登録処理は握りつぶしています）。
- iOS Safari は Service Worker の挙動に制限がありますが、キャッシュが効かなくても
  ネットワーク経由で動作します。

### 10-2. 更新のしかた

```powershell
# 1. ファイルを直す（問題を直すときは統合CSV → python tools\csv2json.py）
# 2. コミットして送る
cd C:\Users\takad\Downloads\QA_APP

git push
```

**push から数分でサイトに反映されます。** 状態は次で確認できます。

```powershell
gh api repos/narulab-jp/qa-app/pages --jq .status   # built になれば反映済み
```

**アプリのファイル（index.html / app.css / app.js など）を変えたときは、
`sw.js` の `VERSION` を上げてください。** 上げないと、以前のキャッシュが
残っている端末に更新が届きません。

```javascript
var VERSION = "v2";   // → "v3" のように上げる
```

### 10-3. 公開しないもの

**学習ログと間違いノートはリポジトリに含めません。** 学習の記録は個人の情報であり、
公開する必要がないためです。`.gitignore` で除外しています。

```
*_note.json      間違いノート
*_log.json       学習ログ
*_resume.json    中断した周回の状態
学習ログ/
```

これらは各自の端末にダウンロードして保管してください（8節を参照）。

また、ソースコード中に個人情報が入らないよう、絶対パスは
`os.path.expanduser("~")` や `%USERPROFILE%` で書いています。

## 11. 複数の利用者に対応する仕組み

家族の複数人が同じアプリを使えます。**ログインもパスワードもありません**（家庭内で使うため）。
**サーバーには何も保存しません。** 記録は従来どおり各自の端末にファイルとして持ちます。

### 11-1. 利用者の扱い

- 起動時に利用者を選びます。1人しか登録されていないときは自動で選ばれます。
- 人数の上限はありません。名前は自由入力（日本語可）で、変更・削除もできます。
- **画面の上部に「〇〇 として学習中」を常に表示**します。別人の記録に書き込む事故を防ぐためです。
- 学習中でも［切り替え］から切り替えられます（確認が出ます）。

### 11-2. 保存されるファイル

| 種類 | ファイル名の例 |
|---|---|
| 間違いノート | `chiri_note_長男.json` |
| 学習ログ | `chiri_log_長男.json` |
| 中断した周回 | `chiri_resume_長男.json` |

ファイル名に使えない文字（`\ / : * ? " < > |` と空白）はアンダースコアに置き換えます。
**画面に出る表示名はそのままです**（例：表示「三男 / テスト」→ ファイル名 `chiri_note_三男___テスト.json`）。

### 11-3. データの中身

ノートと学習ログには `user`（利用者名）と `users`（登録されている利用者の一覧）が入ります。
利用者の一覧もノートと一緒に保存されるため、ノートを1つ読み込めば全員の一覧が戻ります。

### 11-4. 読み込み時の照合

- **別人のノートは黙って読み込みません。** 「このノートは『次男』のものです。今は『長男』として
  使っています。読み込みますか。」と確認し、［次男に切り替えて読み込む］／［いいえ（戻る）］を選べます。
- `user` を持たない古いファイル（複数利用者対応より前に保存したもの）は、
  現在の利用者のものとして読み込み、その旨を画面に表示します。エラーにはしません。

### 11-5. 設定

設定（卒業に必要な連続正解数・既定の出題数・音声の自動開始・文字サイズ）は
**利用者ごとに別々**です。ノートの保存ファイルに同梱されます。

### 11-6. 実装していないこと

学習ログの比較画面は作っていません（将来やりやすいよう、ログに `user` を入れるところまで）。

## 12. 図表・読図編（4択のマーク式）

共通テストと同じマーク式の練習用。声ではなく選択肢を押して答えます。

### 12-1. 形式はデータが決める

科目データの `format` で画面が変わります。アプリに科目名は書いていません。

| `format` | 画面 |
|---|---|
| 省略 または `"voice"` | 声（またはキーボード）で答える。従来の一問一答 |
| `"choice"` | 図を表示し、①〜④のボタンで答える。マイクは出さない |

### 12-2. 問題の書き方（`data/chiri-zuhyo.json`）

```json
{
  "no": 1, "seq": 1, "setId": "A-01", "skill": "縮尺と距離", "level": "S",
  "type": "縮尺と距離",
  "figures": ["figures/A01_map.svg"],
  "q": "…実際の距離はおよそ何mか。",
  "choices": ["250m", "500m", "1000m", "2000m"],
  "answer": 2,
  "a": "③ 1000m",
  "exp": "…",
  "grounds": ["…", "…"]
}
```

- `answer` は `choices` の **0 から始まる添字**
- `a` は正解の表示用。間違いノートと印刷が従来のしくみのまま使える
- `figures` は複数指定できる（冊Cは資料2点）
- **`setId` が同じ問題は同じ資料を共有する。** アプリは図を読み直さない

### 12-3. 図版

`figures/*.svg` はすべて `tools/make_figures.py` が計算して描いています。
教科書・資料集・過去問の図は使っていません。地形図は等高線を高さの式から
起こした訓練用の模式図、雨温図と統計は架空の地点・国です。
色は使わず、線種・ハッチング・記号で区別しているので白黒印刷でも読めます。

### 12-4. 作り直す手順

```powershell
cd C:\Users\takad\Downloads\QA_APP
python tools\make_figures.py      # 図版（SVG）
python tools\build_zuhyo.py       # data/chiri-zuhyo.json ＋ データの検算
python tools\build_zuhyo_pdf.py   # 紙で解く版のPDF
python tools\test_zuhyo.py        # データ・アプリ・PDFをまとめて確認
```

PDFの出力先は `CHIRI_QA_20260901\PDF\`。

### 12-5. 間違いノートは科目ごとに分かれる

ファイル名は科目の `subjectId` から作るので、自動的に分かれます。

```
chiri_note_長男.json          一問一答
chiri-zuhyo_note_長男.json    図表・読図
```

### 12-6. 科目の切り替え

**画面のいちばん上、利用者名のすぐ下**に科目のタブが出ます。
ホームと単元選びの画面でだけ出て、出題中は出ません
（解いている途中で切り替わらないようにするため）。
起動時は subjects.json の最初の科目が選ばれます。
